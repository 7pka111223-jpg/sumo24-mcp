# Runtime and result contract

The standard simulation tools and custom-unit tracers share `PY/sumo_runtime.py`. It installs the scheduler callbacks once per scheduler instance and routes rows and completion by job ID. Scheduling is serialized. Events arriving before `schedule()` returns are replayed only for the returned ID. A foreign job can neither complete a tracer nor contribute its data.

Jobs terminate as `finished`, `failed`, `timed_out`, or `cancelled`. A finished message without data is a failure. Rejected commands prevent a successful result. MCP cancellation stops the native jobs owned by that request. Shutdown stops remaining owned jobs. The runtime retains at most 128 job records, evicting completed records first, and at most 100,000 rows per job. Status and CSV export report truncation; callers needing a full long time series should select a suitable DataComm interval and export before record eviction.

`PY/runtime_results.py` resolves effluent symbols from the selected state file. One unambiguous effluent is selected automatically; `SUMO_EFFLUENT_UNIT` selects a different or ambiguous location. `SUMO_INFLUENT_UNIT` similarly selects the inlet for explicit influent overrides. Unsupported inputs fail before scheduling. BOD uses `TBOD_5`, total COD uses `TCOD`, and soluble COD remains a separate observation. SUMO time in milliseconds is converted to days. Result observations include the native symbol, unit, source, and quality.

Compliance has three outcomes: `COMPLIANT`, `NON-COMPLIANT`, and `INSUFFICIENT_DATA`. All configured TSS, BOD5 and total-COD measurements must be finite and nonnegative. Missing data, soluble-COD-only data, unknown jobs and incomplete jobs cannot pass. This is an evaluation of the configured limits, not a certification of legal applicability or model calibration.

The saved-project compatibility adapter queues edits and reports `queued` with `live_confirmed: false`. It never guesses a live job from its numeric ID. Its reads identify saved data or pending overrides. Selecting a different project or state clears the previous pending edits. Saved-project edits cannot be applied to a separately configured native model implicitly. Save and recompile topology edits before starting a native run. Native parameter commands are consumed only after the scheduler accepts a job.

`PY/tool_registry.py` binds advertised schemas and names to callable handlers and rejects duplicate definitions or unknown dispatch targets. Individual families can replace their compatibility handler without changing their advertised contract. Legacy tool implementations execute on one worker thread, keeping native/project/GUI mutations serialized while MCP status and compliance requests remain responsive. The transport returns structured MCP failures and an operation ID. Optional-import warnings go to stderr. Native job cancellation is supported; cancellation of a running external compiler or GUI modal operation remains dependent on its adapter and timeout. A dedicated native worker process and migration of the remaining legacy helper implementations into separate application modules remain architectural follow-ups.

Stage 8 requires meaningful schematic references and recorded native validation evidence with matching schematic, DLL and state hashes. An exports-only inspection cannot mark a project ready. DynaSand scheduling merges saved doses and pending dose commands and rejects simultaneous positive alum and ferric doses.

Portable regressions: `python -m unittest discover -s tests -p test_runtime_review.py -v` from the MCP directory. Native integration evidence is maintained separately in `docs/reviews`.
